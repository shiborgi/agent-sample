# Revisão de segurança

- Entrada externa (requisição, arquivo, variável de ambiente, argumento) chega a SQL, shell,
  caminho de arquivo, template ou desserialização sem validação? Aponte como `security`.
- SQL montado com concatenação ou f-string é `critical`; use parâmetros.
- `subprocess` com `shell=True` e texto vindo de fora é `critical`; passe uma lista de argumentos.
- Caminho de arquivo vindo de fora precisa ser confinado a um diretório (resolva e compare).
- `pickle`, `yaml.load` sem `SafeLoader` e `eval` sobre dados externos são `critical`.
- Checagem de permissão removida ou feita depois da ação é `major`.
- Segredo, token ou senha no código ou em log é `critical`, mesmo em teste.
- Erro que devolve detalhes internos (stack trace, SQL) ao cliente é `minor`.
